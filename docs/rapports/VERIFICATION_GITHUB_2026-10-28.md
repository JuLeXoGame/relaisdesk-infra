# Vérification GitHub — 28 octobre 2026

Vérification commencée le 28 octobre et finalisée le 29 octobre 2026, heure de Paris. La version produit RelaisDesk reste 1.0.0. Cette intervention ne modifie aucun fichier dans `relaisdesk/` et ne déploie rien sur OVH ou Oracle.

## Correctifs déjà vérifiés

- Le test Linux attend désormais le véritable canal IPC du processus de bureau lancé dans une session contrôlée. La compilation complète [40659491075](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40659491075) a réussi, notamment le test réel du paquet DEB. Les trois tests simulant une course au démarrage, un plantage et un rejet du mot de passe ont passé lors de la préparation du correctif.
- Le réglage GitHub Actions autorisant la création de demandes de fusion a été activé avec l’accord de l’exploitant ; les permissions générales restent en lecture seule. La mise à jour des certificats [40658294874](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40658294874) a réussi et créé la [demande client nº 6](https://github.com/JuLeXoGame/relaisdesk/pull/6), laissée ouverte pour examen.
- La [demande client nº 7](https://github.com/JuLeXoGame/relaisdesk/pull/7) a été fusionnée avec accord explicite. Le générateur Python Brotli 1.2.1 a été testé avec trois fichiers et les niveaux 1 et 11 ; le décodeur Rust utilisé par le programme lit les deux résultats.
- L’ancien échec de conditionnement macOS est déjà corrigé. La reconstruction des paquets ARM et Intel [39920735454](https://github.com/JuLeXoGame/relaisdesk-infra/actions/runs/39920735454) a réussi. Les anciens historiques rouges sont conservés.

## Client et sous-module commun

Le sous-module commun est publié au commit `388c6d3` sur `codex/github-security-webrtc-20261028`, avec accord explicite de l’exploitant. Le transport WebRTC facultatif utilise webrtc/rtc 0.21.1 et le fournisseur cryptographique ring, ce qui retire l’ancienne chaîne crypto-bigint/DTLS. Les interfaces publiques et la signalisation JSON/base64 sont conservées. La taille des descriptions SDP, des messages et des files de réception est limitée ; les envois respectent leur délai et les erreurs ferment la session.

Les neuf tests WebRTC couvrent les échanges binaires jusqu’à 65 535 octets, l’ordre des messages, la saturation puis la reprise de la file de réception, la fermeture d’un lecteur en attente, le délai d’une connexion sans réponse, les entrées invalides et le rejet d’une empreinte DTLS falsifiée. Ils passent sous Windows localement ainsi que sur Windows et Linux dans GitHub.

Les mises à jour ctutils, Tokio et Zstandard éliminent les avis bloquants restants. Trois tests de décompression passent, dont la lecture d’une trame produite par l’ancien encodeur. Une vérification séparée confirme la compatibilité Zstandard dans les deux sens sur cinq tailles et quatre niveaux de compression.

Le commit client initial `1e1cc34019aafcf76d3fb4ada47655874bd0aaff` a passé les six jobs du [contrôle de sécurité 40731402233](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40731402233) : audit, régressions natives Windows/Linux, transfert de fichiers Linux et régressions WebRTC Windows/Linux. L’audit cargo-audit 0.22.2 avec base RustSec actualisée trouve zéro vulnérabilité et zéro avertissement `unsound`, sans avis ignoré. Les 23 avertissements de maintenance et les deux versions retirées restent visibles.

Les workflows utilisent Rust 1.99.1. Le compilateur Windows i686 est un nightly récent utilisant l’hôte natif du runner et une cible i686 distincte. L’étape d’installation du compilateur, auparavant en échec, passe. Les premières constructions générales ont rencontré des erreurs HTTP 502 pendant la récupération de tout l’historique Git AOM sur macOS Intel et Windows x64.

Le commit applicatif `2c074a088c4980562a66d2788c7cdd744f4b0211` de la [demande nº 9](https://github.com/JuLeXoGame/relaisdesk/pull/9) utilise l’[archive officielle AOM 3.14.1](https://aomedia.org/blog%20posts/AOMedia-Announces-Availability-of-Libaom-v3_14/) avec vérification SHA-512. La comparaison des 1 445 fichiers confirme leur identité avec le commit précédemment épinglé. Le port est réellement reconstruit sous Windows en debug et release ; le test `AOM SVC bounds` passe avec la bibliothèque reconstruite. Les six jobs de sécurité du [contrôle 40735445136](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40735445136) et le [contrôle Linux classique 40735445110](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40735445110) réussissent. La [construction générale 40735445265](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40735445265) a également validé Linux DRM, Android ARM 32/64 et Android x86_64 ; les autres plateformes sont suivies. Les deux constructions du précédent commit 1e1cc3401 ont été arrêtées après publication du nouveau commit pour libérer les runners.

Les ajustements CI suivants ne modifient plus les sources applicatives :

- Le runner macOS ARM utilise `macos-15`. GitHub a annulé la tâche sur `macos-14` faute de capacité, et [annonce le retrait de cette image le 2 novembre](https://github.blog/changelog/2026-10-01-github-actions-macos-14-runner-image-retirement/).
- Le contrôle Linux conserve les fichiers compilés entre construction et tests, au lieu d’exécuter un `cargo clean` complet qui impose une deuxième compilation.
- Le compilateur i686 utilise un hôte Rust et LLVM 64 bits avec cible 32 bits explicite pour le client et le packer. Les chemins de sortie sont corrigés et les deux exécutables sont contrôlés comme PE x86. Le premier changement d’hôte Rust avait laissé LLVM 32 bits, cause identifiée dans le journal de compilation et corrigée.

Le nettoyage du test Linux a ensuite été corrigé : il pouvait attendre indéfiniment si le rejet arrivait avant la création de la session du serveur. Les signaux ciblent désormais le processus et son groupe, avec délai d’arrêt borné. Deux régressions supplémentaires couvrent la création de session retardée et un processus ignorant SIGTERM. La première reproduit le dépassement de délai avant correction ; les cinq tests passent après correction. Ils s’exécutent aussi au début du workflow complet afin de détecter ces défauts avant les longues compilations.

Le commit `b43180f30f95da679d2e6871ad99e7f6c557aa14` a passé [ses contrôles de sécurité](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40745548657) et [le contrôle Linux classique](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40745548660). Sa [matrice complète 40745549403](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40745549403) a validé Windows x64 et ARM64, macOS Intel, les trois cibles Android, Linux DRM et le paquet DEB. Le journal du paquet DEB confirme les cinq régressions puis l’acquittement réel `Done!` du serveur installé. macOS ARM a été annulé sans machine attribuée, avec avertissement explicite de capacité GitHub.

Le dernier défaut i686 provenait de `libsodium-sys` 0.2.7 : son script choisit le binaire natif selon l’architecture de l’hôte et fournit une bibliothèque x64 à la cible x86. Le correctif utilise la [configuration native par cible de Cargo](https://doc.rust-lang.org/cargo/reference/build-scripts.html#overriding-build-scripts) pour sélectionner la bibliothèque x86 déjà contenue dans le paquet verrouillé, sans modifier le paquet ni le verrou. Un projet local utilisant simultanément libsodium comme dépendance hôte x64 et comme dépendance x86 reproduit l’échec avant correction, puis compile et exécute le programme x86 après correction. Ses sorties de chiffrement sont identiques à celles de l’hôte, et le déchiffrement réussit ; l’exécutable produit est bien un PE x86 (`0x14c`).

Le correctif natif est publié au commit `774fbffb4ae8fd5ad75b355920b8994aa83506b1`, puis la lecture UTF-8 des métadonnées Cargo est explicitée au commit final `421877211d56733097ae5585db25d92386434ed4`. Le projet complet reproduisait un échec de décodage avec la page de codes Windows ; sa lecture en UTF-8 et la sélection du paquet attendu sont vérifiées localement. Les six contrôles de [sécurité 40774895401](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40774895401) et le [contrôle Linux 40774895399](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40774895399) réussissent sur ce dernier commit.

Toute la [matrice complète 40774895453](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40774895453) réussit sur le commit final `421877211d56733097ae5585db25d92386434ed4`. Le [job i686 123121588871](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40774895453/job/123121588871) valide le client, le programme portable et le contrôle PE x86 des deux exécutables. Les jobs [macOS ARM 123123030037](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40774895453/job/123123030037) et [macOS Intel 123123030088](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40774895453/job/123123030088) réussissent tous deux, ainsi que Windows x64/ARM64, les trois architectures Android et Linux DEB/DRM. Après cette validation et conformément à l’autorisation explicite, la [demande nº 9](https://github.com/JuLeXoGame/relaisdesk/pull/9) est fusionnée au commit `a5043e4ed97c80412d25c39a0d91b8be4c402be4` le 29 octobre à 00:00:25, heure de Paris. Les corrections réutilisent le sous-module commun publié ; la comparaison confirme qu’aucun fichier du protocole ne change. Les deux audits Rust corrigés trouvent zéro vulnérabilité et zéro avertissement `unsound`. Les avertissements de maintenance restent visibles : trois pour le serveur, quatre pour son ancienne interface.

Les corrections sont publiées jusqu’au commit `6099f0b358705889116040155098a49849563b73` dans la [demande serveur nº 2](https://github.com/JuLeXoGame/rustdesk-server/pull/2). Les trois jobs de sécurité [40733566161](https://github.com/JuLeXoGame/rustdesk-server/actions/runs/40733566161) passent, y compris la compilation et les régressions de l’ancienne interface Windows. ## Infrastructure et limites

Le workflow `.github/workflows/build-macos.yml` pointe sur les sources applicatives corrigées au commit `2c074a088`, utilise Rust 1.99.1 et refuse également les avertissements `unsound`. Les commits client suivants ne changent que la configuration CI, sans incidence sur ce workflow. Cette correction est publiée au commit infrastructure `40c2c0f`. Sa validation actionlint passe en tenant compte du label GitHub `macos-15-intel`, absent du catalogue de l’ancien outil local et déjà utilisé avec succès sur GitHub. La reconstruction complète avec cette nouvelle référence n’a pas encore été lancée.

La branche principale d’infrastructure était encore en retrait de 21 commits par rapport à la branche dédiée déjà publiée. La [demande infrastructure nº 1](https://github.com/JuLeXoGame/relaisdesk-infra/pull/1) synchronise ces sources, y compris le correctif des noms de dossiers du parc dans l’application Technicien. Après réussite des deux jobs [40784413755](https://github.com/JuLeXoGame/relaisdesk-infra/actions/runs/40784413755), elle a été rendue prête à examiner, puis fusionnée avec l’autorisation explicite de l’exploitant au commit `de0b6b5a912b94c4c16567f167fb8a29d30583bc`, le 29 octobre à 00:06:36, heure de Paris. Les deux jobs [40784980771](https://github.com/JuLeXoGame/relaisdesk-infra/actions/runs/40784980771) réussissent également sur `main`. La fusion ne déclenche aucun déploiement : seuls les tests et audits automatiques s’exécutent sur `main` ; les constructions macOS nécessitent une action manuelle ou un tag.

L’audit Go actualisé ne relève aucun appel vulnérable dans les huit modules. Il a cependant signalé deux avis dans le parseur/rendu HTML de `golang.org/x/net` 0.60.0 (GO-2026-6860 et GO-2026-6866), sans appel des symboles concernés. Le commit `318140b0ca3293b1768143d96deca2aca6923800` passe les trois interfaces Go à x/net 0.62.0, avec les minima x/sys 0.49.0 et x/text 0.43.0. Les trois programmes sont de nouveau testés et audités. L’avis GO-2026-5932 sur OpenPGP abandonné reste visible dans les modules x/crypto ; aucun paquet OpenPGP n’est importé par les modules contrôlés et il n’existe pas de version corrigée de cette API abandonnée.

Les tests locaux ont aussi révélé deux défauts de la suite de validation : l’assertion Unix `0600` était exécutée sous Windows, où Go ne gère que l’attribut lecture seule ; le programme C autonome AOM empêchait le chargement du paquet de tests Go. L’assertion de permissions reste active sous Linux et passe avec Go 1.26.10. Les tests de sauvegarde passent sous Windows, les tests d’intégration Go passent après ajout de la contrainte d’exclusion du fichier C, et la recompilation/exécution séparée de ce même test C confirme `AOM SVC bounds: OK`.

Le nouveau workflow `go-regressions.yml` utilise Go 1.26.10, des actions Node 24 épinglées par commit, un jeton en lecture seule et aucun secret de déploiement. Il exécute tests, go vet et govulncheck 1.7.0 sur les huit modules ainsi que les deux contrôles statiques de cohérence du site. Les huit modules ont passé leurs tests locaux, avec reprise ciblée des deux échecs corrigés, puis les tests, go vet et audits GitHub sur la demande et sur la branche principale.

Les trois interfaces mises à jour passent de nouveau les tests, go vet et govulncheck sous Windows, sans vulnérabilité signalée. Le premier contrôle GitHub a révélé que deux tests API dépendaient du manifeste de production, absent du dépôt public. Le commit `dc140c67c3f87db0240baae5b3dc7aca947c1b01` utilise des clés générées pour les tests et des manifestes temporaires signés ; le chargement et le rejet d’un manifeste altéré sont contrôlés. Ces tests passent sous Windows et Linux. Le contrôle GitHub suivant [40783432791](https://github.com/JuLeXoGame/relaisdesk-infra/actions/runs/40783432791) valide les tests et go vet des huit modules, ainsi que l’audit ; seul le contrôle statique du site attendait une notice dans un dossier de construction ignoré par Git. Le commit `e9dda36` ajoute un mode explicite `--sources-only` pour le contrôle CI ; le contrôle habituel des paquets générés reste strict par défaut. Aucun fichier du site `relaisdesk/` n’est modifié.

L’avis natif CVE-2025-69277 a également été examiné lors du diagnostic libsodium. Il concerne la fonction bas niveau `crypto_core_ed25519_is_valid_point()` dans les versions antérieures au correctif de décembre 2025. Aucun appel à cette API ni à une arithmétique Ed25519 personnalisée n’a été trouvé dans les sources du client, du serveur, du sous-module commun et des lanceurs contrôlés. Les usages relevés sont les API de signature de haut niveau ; [le mainteneur confirme que les API `crypto_sign_*` ne sont pas affectées](https://00f.net/2025/12/30/libsodium-vulnerability/). Le correctif de compilation sélectionne la bonne architecture de la bibliothèque existante ; cet avis est documenté comme non applicable aux usages relevés, sans prétendre avoir mis à jour toute la bibliothèque native.

Après la fusion client, les six jobs de [sécurité 40784202487](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40784202487) réussissent aussi sur la branche par défaut. GitHub ferme automatiquement la demande Dependabot Rustls nº 8, rendue inutile par les corrections synchronisées. Aucune alerte Dependabot n’est ouverte sur les dépôts client et serveur lors du contrôle final. Les alertes de dépendances GitHub étaient désactivées sur l’infrastructure ; leur activation est confirmée par les API d’activation et de lecture (HTTP 204), avec un premier inventaire vide. Aucune permission générale d’écriture des workflows ni fusion automatique n’a été ajoutée.

La mise à jour des certificats est relancée depuis la branche client fusionnée : [40784412586](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40784412586) réussit et rafraîchit la [demande nº 6](https://github.com/JuLeXoGame/relaisdesk/pull/6) au commit `47f4914fc991b3b049f892d6e8d537abdc1184f3`. Le diff contient uniquement douze lignes de `Cargo.lock` (six ajouts, six suppressions). Les six [contrôles de sécurité 40784754784](https://github.com/JuLeXoGame/relaisdesk/actions/runs/40784754784) réussissent, après lancement manuel nécessaire car les commits du jeton GitHub Actions ne déclenchent pas les workflows de demande de fusion. Cette demande de modification du magasin de confiance reste ouverte pour examen ; elle n’est pas fusionnée.

Les audits Rust, Go et npm valident les dépendances couvertes et les tests couvrent les comportements indiqués ; ils ne constituent pas une garantie d’absence de tout défaut. Les avertissements non bloquants ne sont ni masqués ni présentés comme corrigés. Les trois fusions autorisées sont réalisées ; aucun binaire n’est publié et aucun service de production n’est déployé lors de cette intervention.
